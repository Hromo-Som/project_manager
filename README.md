## 📝 Что я вынес из этого проекта

В процессе работы над проектом я усвоил несколько ключевых принципов и лучших практик работы с SQLAlchemy:

---

### 🧩 Декларативный стиль
Современный подход с аннотациями типов (`Mapped`) делает код чище, читаемее и безопаснее. Использование `mapped_column()` вместо устаревшего `Column()` позволяет IDE и mypy лучше понимать код и предотвращать ошибки на этапе разработки.

### 🗃️ Миграции (Alembic)
Alembic — мощный инструмент, но требует внимания при работе с **SQLite**:
- Для изменения существующих таблиц нужно использовать `batch_alter_table`
- Важно указывать имена ограничений (`constraint names`) вручную, чтобы избежать ошибок при удалении
- При работе с `ondelete='CASCADE'` необходимо включать `PRAGMA foreign_keys=ON` для SQLite

### 🔗 Связи и каскады
Каскадное удаление нужно настраивать **на двух уровнях**:
- **ORM-уровень**: `cascade="all, delete-orphan"` в `relationship()` — управляет поведением при работе через сессию
- **БД-уровень**: `ondelete="CASCADE"` в `ForeignKey()` — гарантирует целостность данных при прямых SQL-запросах

Лучшая практика — использовать **оба подхода одновременно**.

### ⚡ Асинхронность
Асинхронный SQLAlchemy (`AsyncSession`, `asyncpg`) требует явного управления ресурсами:
- Всегда вызывайте `await async_engine.dispose()` при завершении приложения
- Используйте `async with` для сессий и транзакций
- Синтаксис отличается: `await session.execute()`, `result.scalars().all()`

### ❗ Ошибки и транзакции
При возникновении ошибки сессия переходит в состояние `PendingRollbackError`.  
**Важно:**
- Всегда обрабатывайте исключения (`try/except`)
- Вызывайте `session.rollback()` при ошибке, если планируете продолжать использовать сессию
- Используйте `with session.begin():` для автоматического управления транзакциями

### 🔍 Профилирование и отладка
Чтобы понимать, что происходит под капотом SQLAlchemy:
- Включайте `echo=True` при создании `Engine` для вывода SQL-запросов в консоль
- Используйте логирование (`logging.getLogger('sqlalchemy.engine').setLevel(logging.INFO)`)
- Следите за **N+1 проблемой** — используйте `selectinload()` и `joinedload()` для оптимизации запросов
- Настраивайте пул соединений (`pool_size`, `max_overflow`) для production-окружения
